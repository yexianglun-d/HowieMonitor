# 采集端版本与受控升级

2026-10-21：源码实现，已完成生产项目构建；尚未运行升级功能测试、生成新安装包或部署。不能把本页当作 Windows 升级与回退验收记录。

## 使用与授权

电脑总览的卡片显示采集端版本和构建标识，“版本与升级”打开这台电脑的状态窗口。硬件信息也显示完整构建标识及本机升级授权。

旧版采集端没有升级通道，必须先在目标 Windows 11 x64 上用新版安装包或 CLI 修复一次，再单独开启“允许面板升级”。首次安装默认关闭，修复保留原选择。此授权与管理员终端授权独立；终端仍只使用已登录的指定管理员账号，不以 SYSTEM 执行用户命令。

后续升级在面板中核对电脑名称、完整 ID、当前/目标版本与构建标识，再输入面板密码确认。每次确认只对应当前采集会话和一个固定的安装包摘要。只允许更高版本；同版本不同构建、远程降级、旧会话和无发布清单的包均不下发。

## 数据与执行边界

- `DeviceRegistration.build` 上报编译时写入的版本、源码提交和升级协议；旧版注册字段保持可用。开发构建使用 `development`，不开放面板升级。
- `agent_updates` 是 SQLite 中按电脑 ID 保存的最新一次任务，不是通用远程任务队列。创建必须通过网页登录、CSRF、限流及密码复验；领取/回执必须使用这台电脑已激活的接入凭据。候选绑定凭据不能领取任务。
- 同一台电脑最多一个未完成任务。创建时要求电脑在线且数据新鲜，不能有活动终端；未完成升级也阻止新建终端。移除电脑时先撤销凭据并删除升级任务，迟到回执不能重新建任务。
- 任务只含设备/会话、版本、摘要和期限；不接收命令、执行参数、任意 URL 或文件路径。下载使用既有同源 HTTPS 分发入口，禁止重定向，并逐块核对大小和 SHA-256。正文使用独立的十分钟取消期限，避免采集上报的四秒超时截断大文件；见 [.NET 超时说明](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpcompletionoption?view=net-10.0)。
- 服务在受保护的 ProgramData 目录暂存安装包、原配置与回退快照；安装账号只读，管理员与 SYSTEM 可写，拒绝链接路径。只直接启动校验后的固定 EXE 和内置维护参数，不调用 shell。
- 新 EXE 的后台入口只允许 SYSTEM，从服务启动独立进程维护本产品。整个安装/验证/回退持有产品级文件锁，与本机安装、卸载互斥；升级期间重启采集服务，原设备 ID、令牌、队列、终端授权 SID 与升级授权继续使用。

## 状态与回退

正常路径为：等待领取 → 下载/校验 → 安装 → 等待上报 → 完成。面板每五秒刷新，采集端每十秒领取。任务有效期二十分钟；尚未取得安装许可的任务到期或会话变化后作废，已进入安装的任务不能只因时间到期被当作失败并重新下发。

升级进程在停止服务前保存原安装标记、配置和安装器，原版本程序目录保留。新版本必须以新采集会话恢复注册、心跳，以及可用的 CPU/内存整机指标；服务端同时核对目标版本/构建与数据新鲜度。服务启动或安装进程返回成功本身不算升级成功。

安装错误或九十秒内未确认新版本上报时，独立进程尝试恢复原配置、服务路径、安装器和 Windows 应用版本，再等待原构建以新会话恢复上报。只有服务端确认后才显示“已回退”。回退结果未确认时保留快照并显示“需要在本机修复”，不会循环下发任务。本机修复后，新会话的回执可解除未完成状态；重新绑定到另一电脑身份时隔离原任务记录。

本地状态原子写入并刷盘，进程 ID 与启动时间防止把复用的 PID 当成运行中的升级程序。采集端成功启动时可续交完成回执，或为中断的安装启动恢复入口。**断电后新旧采集服务都无法启动的情况没有独立开机恢复任务，需要在本机运行修复。** 不能据此宣称任意断电场景都能自动回退。

协议 1 要求新旧版本的本地配置和队列格式兼容。本次没有改变队列 schema；未来破坏性迁移必须设计新的兼容/恢复边界，不能沿用此协议直接发布。

## 发布契约

版本统一取 `Directory.Build.props` 的 `MonitorVersion`，正式发布只接受干净 Git 工作区，`MonitorBuildId` 为完整提交 SHA。安装目录、注册表版本、注册上报和安装器包检查使用同一身份。

完整发布生成 `HowieMonitorSetup.exe`、`.sha256` 和 `.release.json`。清单含版本、源码提交、协议、内嵌 agent ZIP 摘要、EXE 摘要及字节数。Windows 工作流把清单保存为独立的 `howie-monitor-update-manifest-<run id>` artifact，保持 SignPath 的输入仍只有一个 EXE；签名返回后必须重新生成匹配的摘要/大小清单。已有 `publish-unsigned-preview.yml` 也要求同次构建清单，标签使用清单版本。

将同次构建的 EXE 与 `.release.json` 放在服务端 `--setup-package` 指定路径旁；默认是数据目录 `downloads/HowieMonitorSetup.exe` 及 `HowieMonitorSetup.exe.release.json`。清单缺失、格式错误或与当前 EXE 不匹配时，既有手动下载继续可用，面板升级关闭。生产替换期间的旧任务仍固定旧摘要，包已替换时下载失败，必须重新确认。

目前不宣称安装包已签名。HTTPS 和 SHA-256 保证选定文件的一致性，不能代替发布者签名；参见 [签名政策](../CODE_SIGNING.md)。
