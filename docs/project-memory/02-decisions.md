# Decisions

## 2026-10-20 / 彻底移除指定电脑

- 用户选择：删除旧电脑的历史和配置，并撤销接入凭据。以电脑 ID 为边界，不能按电脑名称清理，也不能只隐藏卡片。
- 范围：在线注册/实时/历史/进程快照、通知规则/观察状态/发送记录及相关待绑定请求；结束该电脑终端。其他电脑、共用 SendKey/发送开关/已消耗额度不受影响。重新接入需要新绑定码。
- 边界：面板密码复验后不可撤销；不卸载本机采集端，不清本机数据、备份、运行日志或第三方已收消息。跨 SQLite 与通知 JSON 的清理先撤权并持久化未完成标记，失败后自动续清。
- 状态：accepted。本轮只实现和本地验证，尚未部署，不自动删除已有生产电脑。

- 状态：accepted。没有新增产品范围或生产部署决定。

## 2026-10-20 / 区分温度读数与阈值

- 决策：温度摘要按硬件分组，优先有效的 CPU 主温度、GPU 核心和磁盘综合温度；其他传感器可展开，告警/临界阈值仅在详情以阈值名称展示。
- 原因：真实上报同时包含磁盘温度和较高的 Warning/Critical Temperature；已对照锁定版本 LibreHardwareMonitorLib 0.9.6 的源代码确认这两项来自 SMART 的 TemperatureWarning/TemperatureCritical。
- 影响：不改变原采样和历史身份，不虚构缺失读数，不把阈值当作硬件发热状态。
- 来源：https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/3d331e3370efb858411f19511373eff65a218701/LibreHardwareMonitorLib/Hardware/Storage/StorageDevice.cs
- 状态：accepted。

## 2026-10-20 / 菜单对齐与克制动效

- 决策：按用户要求统一 8 个菜单的视觉边界和间距；动效只用于切页、控件反馈和 Toast。切页整体轻移 4px、持续 220ms，不逐卡片错峰、上浮或缩放。
- 约束：实时采样刷新不重播；键盘切页直接展示；遵循系统减少动态效果偏好，快速切换和缓存页面停用时清理上一段动效。
- 验证：使用内置浏览器在隔离实例检查响应式页面与真实 DOM 动画帧，不以合成样本冒充生产采集结果。
- 状态：accepted。

## 2026-10-20 / GPU 按显卡独立展示

- 决策：用户明确选择“分别显示每张显卡的名称、占用和曲线”。运行总览和电脑摘要不再只取第一张显卡；同型号显卡也按传感器硬件 ID 区分。
- 取值：每张卡优先可用的核心占用，缺失时可使用该卡的 D3D 3D 并标注指标含义；不把显存、总线或功耗百分比当作核心占用，不相加或用最大值冒充单个总占用。
- 影响：曲线继续查询原来的指标身份和电脑 ID；真实零值保留，缺失/过期读数不补零。无需更改 Windows 采集端或数据库结构。
- 状态：accepted。

## 2026-10-20 / 多电脑总览与通知规则隔离

- 决策：用户明确选择“通知规则也按电脑独立配置”。同一私人面板集中展示摘要，详情、规则、草稿、观察状态和发送记录都有明确电脑归属。
- 发送渠道：SendKey、发送总开关和每日请求额度仍共用，在页面独立标为全局发送设置；保存单台规则不修改这些设置，也不取消其他电脑的待发任务。
- 迁移：旧共用规则一次性复制为当时已接入电脑的独立副本。新电脑默认无规则；旧版无法确认归属的发送记录保留在全局历史区，旧版未发送的无归属任务取消。
- 验收：相同电脑名、相同硬件指标 ID、相同规则 ID 都不能导致串数据；迟到的读取/保存不能覆盖另一台电脑。明确指定的电脑不存在时，不回退读取另一台。
- 状态：accepted。

## 2026-10-20 / 当前登录管理员账号的远程终端

- 来源：用户要求目标电脑终端支持管理员权限，并明确选择“当前已登录的管理员账号，不保存 Windows 密码；注销后不可用”。
- 决策：安装/修复时独立勾选本机授权，绑定安装账号 SID。服务仅获取该账号的交互登录与提升令牌；挂起创建 PowerShell，核验真实 SID/登录标识/管理员与非 SYSTEM 身份，纳入退出即终止的进程组后才恢复运行。
- 边界：每个会话绑定电脑 ID、采集端会话、Windows 登录和网页登录身份；再次验证面板密码，短期授权只领取一次。不缓存命令或自动重连；离开/切换/断线/权限失效关闭。终端视图独立销毁，避免渲染缓冲串到另一电脑。
- 数据：输入与输出经现有运营者服务器以 HTTPS/WSS 转发，不是端到端加密；不持久化命令/输出，保留生命周期元信息。默认关闭，旧采集端和旧配置不会获得权限。
- 验收：本地协议与界面模拟通过不等于 Windows 提权已验收；真机验收完成后才能发布为可用功能。
- 状态：accepted；实现已落地，Windows 实机验收 pending。


## 2026-10-20 / 用滚动交互补充原有克制动效

- 来源：用户明确提出滚动触发、滚动联动、视差、吸顶、吸附与横向滚动，要求改善页面僵硬和操作体验。
- 决策：在原有切页/Toast/控件反馈之外加入上下文吸顶、段落导航/阅读进度、卡片横向浏览与装饰视差。此决定更新此前“动效只用于切页、控件和 Toast”的范围限制；实时数据不漂移、不随刷新重播和遵循减少动态效果的约束继续有效。
- 边界：原生滚动，不接管纵向滚轮、不自动播放卡片；卡片支持网格切换。键盘立即响应，减少动态效果关闭视差与吸附，快速切页/退出只清理本页的触发器。真实功能、电脑隔离与终端授权语义不变。
- 状态：accepted；本地实现/验证完成，应用 `0959d4a` 已于 2026-10-20 19:12（北京时间）部署。

## 2026-10-21 / 交互式 CLI 安装入口

- 来源：用户要求支持 CLI 安装，并明确选择“交互式命令行：运行后按提示输入绑定码、确认安装和终端授权”。
- 决策：同一安装包增加 `--cli`，默认 GUI 及后台服务运行方式不变；不新增 Node.js/Python 依赖或无人值守安装。CLI 从当前管理员账号的 PowerShell 启动，终端授权仍显式选择并绑定该账号，不保存 Windows 密码。
- 验收：CLI 与 GUI 复用安装引擎/绑定协议及请求记录；绑定响应丢失不能重复创建身份，接管风险必须展示，取消不能视为确认，服务/真实采样/激活未全部通过不能返回成功。卸载待重启保护不绕过。
- 状态：accepted；`c67e088` 安装包已发布，Windows 自动化用例及打包入口检查通过，目标电脑完整交互安装待实机确认。

## 2026-10-21 / 单命令下载安装

- 来源：用户希望一条命令自动下载安装，再按提示输入绑定码，不先手动下载 EXE。
- 决策：提供公开只读的安装引导与摘要固定的 EXE 分发入口；原面板 API/设备接入授权保持原有认证。命令不包含绑定码，不读浏览器 Cookie；下载通过大小和 SHA-256 校验后启动同一 CLI，保留显式安装确认和默认关闭的终端授权。
- 状态：accepted；服务端和页面已上线，Windows 自动化通过，目标实机安装仍待执行验证。
